# 福清麻将 · 融城茶馆 v1.2.0 联机设计

本版在 Godot Windows 版加入四座联机房间。真人可以和朋友同桌，房主可以用 AI 补位。房间沿用现有福清麻将规则和整桌计分。

## 1. 开房、加入与邀请

开始页的「联机模式」提供「开房间」和「加入房间」。两条入口都要求填写自己的昵称。

| 流程 | 玩家操作 |
| --- | --- |
| 开房间 | 输入昵称和监听端口，默认 UDP 36712。开房成功后，进入等候室并获得房主权限。房间页展示可用局域网地址、端口和随机邀请码，支持一次复制整段邀请。 |
| 局域网加入 | 朋友粘贴整段邀请，或分别输入房主局域网地址、UDP 端口和邀请码，再点击「加入房间」。电脑有多个网卡地址时，房主可选择与朋友同网段的地址。 |
| 内网穿透加入 | 房间承载端配置支持 UDP 的穿透服务，把外部 UDP 端口映射到游戏的本地监听端口。在房间页填入穿透的外部域名或 IP 和外部端口，即可复制穿透邀请。朋友使用同一个「加入房间」入口。 |

邀请包含游戏版本、可达地址、UDP 端口和邀请码。承载端校验版本、邀请码和座位容量。遇到端口占用、连接超时、邀请码错误、房间满员、昵称重名或已开局时，界面给出相应提示。发布版随附局域网与 UDP 穿透的设置示例。

联机使用 Godot 的 ENet，局域网直连和穿透都走 UDP。穿透地址由房主所用的服务提供，可用支持 UDP 转发的 frp 配置把外部端口映射到本机端口。[Godot ENet 文档](https://docs.godotengine.org/en/stable/classes/class_enetmultiplayerpeer.html) · [frp UDP 转发文档](https://gofrp.org/en/docs/features/tcp-udp/)

## 2. 房间设置与房主权限

- 等候室展示四个座位、每位玩家的昵称、真人或 AI 标记、AI 难度和房主标记。四个座位都有人或 AI 时，房主可以开始游戏。
- 玩家可在等候室修改自己的昵称。拟定规则为去掉首尾空格后 1–12 个字符，真人和 AI 共用同一个房间昵称范围，每个昵称在该房间内唯一。座位身份由承载端分配。
- 房主可以在空座添加 AI、移除 AI，并为每个 AI 分别设置昵称和「简单」「普通」「困难」，新增 AI 默认「普通」。
- 房主可在等候室移除通过「加入房间」进入的真人。移除后释放座位、撤销其座位凭据并更新邀请码，房间中的其他玩家继续在线。开局后座位锁定，打完整桌后回到等候室继续设置。
- 房主可以在等候室或对局期间把管理权限转交给在线真人。转交立即生效，所有人都能看到新的房主。接手者可以在等候室设置房间、移除玩家和开局，并可再次移交权限。
- 开房者的游戏进程承载房间。转交权限后，朋友继续使用原地址连接，开房者需要保持游戏进程运行。该进程退出时，当前房间和牌局结束。
- 房主在等候室设定总局数和出牌时间。总局数沿用 1–32 局，默认 15 局。出牌时间为 **15 秒、30 秒、60 秒、不限时**，默认 **60 秒**。开局时锁定本桌设置。
- 联机所有座位统一使用「普通」运气，由承载端对整副牌墙正常随机洗牌。联机等候室将运气显示为固定项。出牌时间仅在联机模式生效。

## 3. 倒计时与超时动作

所有玩家都能看到当前行动者和倒计时。抢牌时显示「等待响应」及当前响应阶段的剩余时间。承载端为每个行动阶段发布截止时间，并以自己收到操作的时刻判定是否超时。及时提交的合法操作按现有优先级和座次判定。

| 牌局阶段 | 计时起点 | 超时处理 |
| --- | --- | --- |
| 自己出牌 | 摸牌或补牌完成，或吃碰后取得出牌权时 | 放弃本阶段可选的自摸、暗杠、补杠等操作，再自动打出一张合法牌。优先打出刚摸到的非金牌，其次按手牌默认排序打出最靠左的合法非金牌。只有金牌可打时，从合法金牌中选一张。 |
| 响应别人弃牌 | 承载端按牌权顺序向当前可响应的真人发布选项时 | 当前已显示的动作按「过」处理，继续判定仍有效的候选动作。取得出牌权的人进入自己的出牌阶段。 |
| 开局特殊胡牌 | 承载端按开局牌权顺序向当前可响应的真人发布三金倒或抢金选项时 | 当前已显示的动作按「过」处理，按开局规则继续判定。轮到庄家出牌时开始出牌计时。 |

### 所有争牌冲突按同一顺序处理

联机沿用单机模式的牌权判定。响应弃牌时，胡优先于碰和明杠，碰和明杠优先于吃，同级由出牌者的下家起按行牌座次判定。开局先判三金倒，再判抢金，同类由庄家起按行牌座次判定。真人和 AI 使用同一顺序。

1. 承载端先向当前优先级最高的座位开放可确认的动作。同一座位有多个动作时，可以一起选择其中优先于其他座位候选的动作。其他座位显示当前在等待谁。
2. 当前座位确认认领时，承载端直接执行，结束这次争牌。当前座位选择「过」或超时时，放弃该阶段已开放的动作，再按顺序处理剩余候选。同一座位尚未开放的低优先级动作也按原顺序等待。
3. 轮到下一位真人且选项出现时，从此刻起给足房主设置的时限。轮到 AI 时，由承载端直接获取其决定。所有候选动作都放弃后，按现有牌规继续行牌。

例如，甲能胡、乙能碰、丙能吃时，先问甲。甲放弃后才问乙，乙也放弃后才问丙。同一张弃牌有多家可胡时，同样先问座次靠前的一家。打开多吃法或多杠法选择窗口时，沿用该阶段的截止时间。阶段结束时自动收起旧选项。选择「不限时」时，界面显示当前行动者，等待其自行提交动作。

## 4. 断线与退出

- 拟为暂时断线的真人保留座位 **60 秒**。客户端在宽限内凭承载端发给本人的座位凭据恢复座位，并重新拉取完整的可见状态。
- 有限时的牌局照常计时，断线座位也按当前阶段的超时规则处理。「不限时」牌局若正在等待断线者，最多等到其断线宽限结束。
- 断线宽限结束后，等候室释放该座位。牌局进行中则由普通难度 AI 从该座位继续到整桌结算，继承原有手牌和积分，座位标注「托管」。真人主动离开时立即按相应的释放或托管流程处理。
- 管理房主断线且房间仍可用时，管理权限交给最早进入房间且仍在线的真人。承载端关闭房间时，所有客户端回到联机入口并显示房间结束。

## 5. 牌局同步与验收

开房者的进程是可信裁判，负责洗牌、发牌、AI 决策、计时、规则判定和结算。客户端提交操作请求，承载端按发送者座位、当前阶段、合法选项及截止时间校验。每个阶段带有唯一标识，同一操作请求最多处理一次，超时后到达或来自过期阶段的操作会被拒绝。房间管理命令同样由承载端校验当前房主权限。

对局进行中，每个客户端只收到自己的手牌与公开桌面状态。牌河、公开副露、金牌、余牌数、倒计时及积分由承载端统一同步。结算时按现有规则公开本局牌面及计分明细。承载端持有完整牌局，由组局的朋友共同信任。

| 验收项 | 通过条件 |
| --- | --- |
| 连接 | 同一局域网的两台电脑能用邀请开局。通过 UDP 穿透，外部网络的客户端能加入并完成一局。 |
| 房间管理 | 真人和 AI 可混合坐满四席，各 AI 使用各自的昵称和难度。移除、移交房主权限与邀请码更新同步到各端。 |
| 计时 | 验证默认 60 秒、四档时间、自动出牌、弃牌响应超时自动过、胡或杠可选时的超时行为。多个客户端显示同一阶段与截止时间。 |
| 争牌冲突 | 验证胡与碰、胡与明杠、碰与吃、多家同级可胡、多人可抢金，以及同一座位持有多个优先级的选项。覆盖真人和 AI 的认领、放弃及真人超时，确认低优先级的选项在轮到时才出现，并获得完整时限。 |
| 公平与一致性 | 所有座位使用普通运气。验证对手暗牌隔离、抢牌优先级、重发与迟到操作、各端整桌积分一致。 |
| 断线 | 验证宽限内恢复、超时托管、管理权限交接和承载端退出。 |

发布物拟包括 Windows x64 可执行文件 **FuqingMahjong-v1.2.0.exe**、Godot 工程、联机设置说明及版本更新记录。
