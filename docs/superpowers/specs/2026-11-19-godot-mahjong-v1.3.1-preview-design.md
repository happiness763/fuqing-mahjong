# 福清麻将 v1.3.1-preview · 牌墙海底、联机确认与牌桌精简设计

- 日期：2026-11-19
- 版本：1.3.1-preview（联机协议同名）
- 范围：牌墙尾数与海底阶段、联机准备与结算确认、牌桌界面精简、AI 托管。
- 不改：牌型判定、计分、吃碰杠优先级、开局掷骰与补花规则、统计口径。

## 1. 牌墙尾数与海底阶段

### 1.1 分区

牌墙尾部改为三个区，从牌尾向牌头依次是：

| 区 | 张数 | 是否可摸 |
| --- | ---: | --- |
| 残牌 | 16 | 否，固定保留 |
| 海底牌 | 4 | 是，只在海底阶段按顺序摸取 |
| 杠保留牌 | 明杠 1 张／暗杠 2 张 | 否，用来抵消杠后补牌对牌墙的消耗 |

正常保留数 = 20 + 明杠数 + 2 × 暗杠数。`明杠`包括吃碰后补杠（`addedKong`）和直接明杠（`kong`）；`暗杠`为 `concealedKong`。杠保留是数量上的保留，不绑定具体牌张：杠后补牌仍从牌尾摸取，系统按新的保留数重新计算可摸张数，从而保证尾部 16 张残牌和 4 张海底牌不被杠消耗。

普通行牌中，`可摸张数 = 牌墙剩余 - 保留数`。摸牌后牌墙恰好剩保留数时，当前这一巡仍是完整的一巡（可自摸、可出牌、可正常争牌），从下一家应摸牌时进入海底阶段。

### 1.2 海底阶段

- 进入时机：轮到某家正常摸牌，但 `可摸张数 == 0`。这一家通常正是“摸走最后一张可摸牌的玩家”的下一家；如果最后一张弃牌被人吃/碰，则以实际轮到摸牌的那家为起点。海底阶段的起点固定为这家，之后按东南西北顺序四家各摸一张海底牌。
- 每家摸一张，共 4 张，摸到的牌直接进入手牌参与胡牌判断。
- 摸到可胡的牌立即自动胡牌，不弹操作按钮、不允许放弃；胡牌张记为该海底牌。
- 摸到花牌：只亮出，不计入该家花牌，不补花、不换牌，该家本张不能胡，轮到下一家。
- 摸到金牌：按普通金牌参与胡牌判断；已报金坎者摸到金同样直接胡。
- 海底阶段不允许出牌、吃、碰、杠、抢杠、报听或补花；没有弃牌，也就没有点炮。
- 四家都摸完仍无人自摸，则流局，结算标题显示“海底流局”。

### 1.3 实现要点

- `rules.gd`：新增 `BASE_RESERVE = 16`、`SEA_COUNT = 4`、`RESERVE = 20`；提供 `reserve(open_kongs, concealed_kongs)`。
- `game.gd`：
  - 所有 `Rules.RESERVE` 判断改为动态 `reserve()`：摸牌、杠的可用性、`view.remaining`。
  - 摸牌入口发现可摸张数为 0 时，进入 `phase = "sea"`，并启动海底队列，而不是立即 `finish(draw)`；最后一张正常摸牌的一家仍完成本巡。
  - 进入海底时从 16 张残牌上方取出 4 张海底牌（杠保留牌留在墙内，不参与摸取），记录 `sea_queue`、`sea_index`、`sea_seat`。
  - `advance_sea()` 每次给当前座位发一张海底牌，返回 `{seat, tile, won}`；四张发完或有人胡牌后结束。
  - `view` 增加 `reserve`、`sea`（`remaining`、`seat`、`drawn`）字段，联机快照自动携带。
- `table.gd`：海底阶段用 0.6–0.8 秒间隔播放摸牌，显示“海底 3/4”之类的计数；无人胡时显示流局结算。
- `online_room.gd`：由主机按同样的间隔推进 `advance_sea()` 并广播快照；客户端只负责演出和显示。

### 1.4 显示

- 左上角“可摸 N 张”继续显示普通可摸张数；进入海底后改为“海底 N/4”。
- 牌墙尾部的 4 张海底牌在墙面上用浅金色描边标出，残牌和杠保留牌不标。
- 流局结果与现有流局一致，在统计中记为一局流局，不触发首巡重发。

## 2. 联机准备

### 2.1 状态

- 每个座位新增 `ready: bool`。真人默认未准备；AI 座位始终已准备。
- 准备状态随快照广播，所有客户端都能看到四家的“已准备/未准备”。
- 房主也是四家之一，同样需要准备。

### 2.2 变更时机

- 真人点“准备/取消准备”立即切换。
- 换座、调座、移出座位：受影响座位重新变为未准备。
- 修改局数或出牌时间：四名真人全部回到未准备，需要重新确认。
- 断线：该真人变为未准备；重连后保持未准备，需要重新点。
- AI 补位或被替换为 AI：该座位自动已准备。
- 从结算返回等候室：所有真人回到未准备，AI 保持已准备。

### 2.3 开局条件与界面

- 「开始游戏」仅在以下全部满足时可用：房主本人、四个座位都有人/AI、四家都已准备、房间设置已保存、无断线重连中。
- 等候室右侧新增「准备 / 取消准备」按钮（约 `Rect2(776, 620, 180, 42)`），房主和客人都能看到。
- 每个座位行的说明文字追加“· 已准备”或“· 未准备”；座位汇总显示“已准备 3/4”。
- 房主未准备时，「开始游戏」禁用，提示“请先准备并等待其他玩家”。

## 3. 每局与终局结算确认

### 3.1 规则

- 联机每局结算后，四家各点一次「下一局」；四家都确认后，主机才调用 `next_round()` 开下一局。
- 终局结算后，四家各点一次「返回房间」；四家都确认后，主机才清空牌局并回到等候室。
- AI 座位和断线真人自动视为已确认。断线真人立即计入，避免整桌卡死；其座位仍按现有逻辑保留以便重连。
- 单机模式不变：AI 自动确认，玩家点一次「下一局」立即继续。

### 3.2 数据与流程

- `online_room.gd` 在每次进入 `result` 时建立 `result_votes = [false, false, false, false]`，AI 座位和断线座位直接置 true；本地 AI 托管的真人座位仍需本人确认。
- 客户端点按钮发送 `next` 或 `lobby`（带当前 `stage`），主机把它记录为该座位的投票并广播快照，不再直接推进。
- 最后一家确认后：未终局执行 `_game.next_round()`；已终局清空牌局回等候室。投票与局号/阶段绑定，换局自动清空。
- 现有的“任意玩家点下一局就推进”行为改为只记录投票，不再直接推进。

### 3.3 界面

- 结算弹窗右侧按钮对所有人显示「下一局」或「返回房间」，不再显示“等待房主”。
- 点击后按钮变为「已确认 · 等待 2/4」，并禁用；弹窗底部显示四家确认状态（如“你 ✓　阿岚 ✓　阿榕 ·　阿屿 ·”）。
- 客人点「查看牌桌」关闭弹窗后，仍可从底部操作条的同一按钮投票；投票状态随快照刷新。
- 所有确认后主机推进，各端弹窗关闭并进入下一局或等候室。

## 4. 牌桌界面精简

### 4.1 删除

- 删除最右列（`x=1083..1252`）：本桌积分列表、行牌动态、牌桌状态、本桌统计和侧栏背景面板。
- 删除外圈木框、内圈描边和四角装饰线；桌布铺满整个窗口。
- 删除“行牌动态”和“牌桌状态”文字。局内所需提示改由控件本身表达（当前座位金环、浮动操作按钮、结算弹窗）。

### 4.2 布局

- 牌桌铺满整个设计画布并按比例随窗口缩放：`FRAME`、`FELT` 改为 `Rect2(0, 0, 1280, 800)`，桌面内容铺满全屏；窗口、全屏和 Android 安全区继续按 1280×800 设计稿等比缩放并居中，不再有侧栏或木框留白。
- 牌桌内容在画布中居中：所有牌桌内元素（座位、牌河、桌心、牌墙、手牌、动作条）在 x 方向整体右移 91px，原有相对位置和尺寸不变。新关键坐标：
  - 桌心 `(640, 400)`；牌河：下 `(398, 482, 484, 72)`、右 `(732, 319, 174, 162)`、上 `(398, 205, 484, 113)`、左 `(374, 319, 174, 162)`。
  - 座位：下 `(154, 640)`、右 `(1006, 290)`、上 `(563, 40)`、左 `(149, 290)`。
  - 手牌中心 `x = 640`；牌墙中心同步 +91。
- 菜单按钮放在窗口右上角 `Rect2(1148, 16, 104, 40)`，菜单面板在其下方右对齐，宽 150、高 314（7 行：声音、玩法规则、数据统计、AI 托管、移交房主、设置、返回首页）。

### 4.3 头像与积分

- 每个座位的头像框高度从 39 增至 56：上半保留头像、昵称、方位/花数，下半新增积分行。
- 积分行显示本桌累计分（带正负号和颜色），右对齐；庄家/当前行动仍用金色边框。
- 座位 2（上家）的手牌预览和副露整体下移 17px；座位 1、3 的预览同步下移 17px；座位 0 的积分行位于手牌上方（`y≈679..696`），不遮挡手牌。
- 不再显示“累计”列或单独的积分侧栏。

### 4.4 金牌与局数

- 局数“第 01/02 局”和“可摸 N 张”留在左上角。
- 金牌面板缩小到 `Rect2(162, 96, 150, 74)`，放在局数与可摸张数下方：标题“金牌”12px，最多四张 28×37 的小牌并排，下方显示金牌名称/花金/已抢。
- 抢杠提示、开局翻金动画、金牌高亮沿用现有逻辑，只改面板位置与尺寸。

### 4.5 操作条

- 侧栏里的「出牌」「取消选择」「报听金坎」和「结算明细」「下一局/返回房间」「跳过演出」合并到底部浮动操作条：`y=615`、右端 `x=1128`，向左排列，与「过/吃/碰/杠/胡」同一行。
- 同一时刻通常只有 2–5 个按钮（行牌阶段为出牌类，争牌阶段为吃碰杠胡类，结算阶段为结算类），不会超出牌桌宽度。
- 删除侧栏后不再有固定状态文字；需要的等待/确认信息放进结算弹窗或按钮文字。

## 5. AI 托管

### 5.1 入口

- 对局菜单新增一行「AI 托管  关/开」，位于「数据统计」和「移交房主」之间；点击切换并即时生效。
- 托管是本地行为，只控制本机座位 0；联机时仍由本客户端发送正常出牌请求，服务器不需要新权限。

### 5.2 行为

- 开启后，轮到本机操作时延迟约 0.55 秒自动执行，使用 `Opponent.choose()` 和普通难度：
  - 出牌、自摸胡、吃/碰/杠、抢杠、过、开局换金/报听弃牌。
  - 掷骰定庄阶段自动掷骰；补花和开局演出仍按现有动画播放。
- 开启时关闭选择菜单和当前选择，头像框下显示「托管」标记。
- 关闭后立即恢复手动操作；尚未执行的托管计时取消。
- 托管不代点「下一局/返回房间」，也不操作设置、数据统计和互动道具。
- 返回首页或回到等候室时自动关闭；同一桌内跨局保持开启。
- 托管期间互动特效、统计和胡牌演出照常；操作仍记在本机玩家名下。

### 5.3 实现

- `table.gd` 增加 `ai_delegate: bool`；`run_ai()` 在开启时把座位 0 纳入候选，使用现有 `perform()` 路径。
- `refresh()` 在 `ai_delegate` 且本机有可执行动作时启动现有 `ai_timer`；`dealer_roll_auto_roll` 用于自动掷骰。
- 菜单按钮文本与座位标记随开关刷新。

## 8. 已确认

1. 最后一张可摸牌打出后，允许其他家按现有规则吃/碰/胡这张弃牌；海底从实际轮到摸牌的那家开始。
2. 断线真人立即视为已确认，避免卡桌。
3. 桌面铺满全屏并按比例随窗口缩放，牌桌内容居中，不再保留侧栏或木框。
4. 托管使用普通难度，且不代点“下一局”。
5. 版本号采用 1.3.1-preview。
6. 海底摸到花牌只亮出，不计入花牌、不补花，也不能胡。
