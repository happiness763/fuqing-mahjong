# 福清麻将 v1.3.3d 3D 牌桌修复与清晰度优化设计

2026-11-24 · 审阅稿

## 目标与范围

在 `v1.3.3c` 原生 3D 牌桌基础上，集中解决实机游玩暴露出的三类核心视觉与可读性问题：

1. **统一副露与牌山、舍牌的物理厚度**，消除副露偏薄、扁平的观感割裂；
2. **修复 2K 及高分辨率全屏下的牌面与牌背模糊**，让 3D 牌桌按实际物理像素清晰渲染；
3. **系统性消除牌张遮挡**，重点解决对家副露与手牌被对家双层牌墙遮挡的问题，并同步排查四家牌河、左右家副露/立牌以及 2D 操作区与 3D 牌体的遮挡隐患。

本次改动限定在 Godot 3D 渲染与布局层（`table_layout_3d.gd`、`table_scene_3d.gd`、`table_tile_atlas.gd`、`table_tile_atlas.gdshader`、`table.gd` 及对应素材导入配置与回归测试）。规则引擎、计分、AI、联机协议、快照字段与存档格式保持不变；联机版本同步更新至 `1.3.3d`。

## 问题一：副露厚度与牌山、舍牌不一致

### 现状与根因

在 `godot/scripts/table_layout_3d.gd` 中，三类平放牌张的 `height_scale` 不统一：

| 区域 | 当前 `height_scale` | 基准高度 `point.y` | 表现 |
| --- | ---: | --- | --- |
| 牌山（`wall_pose`） | `WALL_THICKNESS = 1.38` | `(TILE_LIFT + storey) * 1.38` | 厚实立体 |
| 舍牌（`river_pose`） | `RIVER_THICKNESS = 1.46` | `TILE_LIFT * scale * 1.46` | 厚实立体 |
| 副露（`_meld_poses`） | 默认 `1.0`（未传参） | `TILE_LIFT * scale` | 明显偏薄、扁平 |

此外，补杠第四张的叠放高度目前写为 `WALL_STOREY * scale`，未乘厚度倍率。

### 设计方案

1. **统一厚度常量**：新增 `MELD_THICKNESS := 1.42`（或与 `WALL_THICKNESS` / `RIVER_THICKNESS` 统一采用 `TILE_THICKNESS := 1.42`，三者视觉完全一致）。
2. **同步抬高副露中心与补杠层高**：
   - 副露每张牌：`point.y = TILE_LIFT * scale * MELD_THICKNESS`，姿态传入 `tile_pose(point, yaw, tilt, scale, MELD_THICKNESS)`；
   - 补杠第四张：`group[source].translated(Vector3.UP * WALL_STOREY * scale * MELD_THICKNESS)`，确保第四张完整落在横放来源牌顶面之上，不穿模、不悬空；
   - 暗杠背面牌同样沿用 `MELD_THICKNESS`，与同组明牌齐平。
3. **本家/外家手牌对照**：本家立牌（`hand_group`）与外家亮牌/立牌（`side_group`）同步核对厚度协调性；外家结算揭牌平放时同样采用 `MELD_THICKNESS`，避免同一侧亮牌与副露一薄一厚。

## 问题二：高分辨率（2K）全屏下牌面与牌背模糊

### 现状与根因

在 2560×1440（2K）全屏下，模糊由**四层降采样/失真叠加**导致：

1. **3D `SubViewport` 分辨率固定死在 `1280×800`**（首要原因）：
   - `table_scene_3d.gd` 中 `_viewport.size = DESIGN_SIZE`（`1280×800`）。
   - `table.gd` 的 `layout_screen()` 在 2K 全屏下将整个 1280×800 画幅放大 `factor = 1.8` 倍（像素面积放大 3.24 倍），`TextureRect` 双线性拉伸直接导致整个 3D 牌桌发糊。
2. **牌面图集单格被过度压缩至 `96×128`**：
   - `godot/assets/tiles/` 下的原始国标与日麻 SVG 本身是 `300×400` 的清晰矢量图，但 `table_tile_atlas.gd` 强制将其缩放到 `INK_SIZE = Vector2i(96, 128)`。在 2K 全屏下本家单张立牌物理尺寸超过 `110×150` px，图集分辨率反而低于屏幕像素密度。
3. **牌背 SVG 导入尺寸小且无 mipmap**：
   - `godot/assets/tile_backs/*.svg` 原尺寸 `128×128`，`.import` 中 `svg/scale=1.0`、`mipmaps/generate=false`。
4. **未启用各向异性过滤（Anisotropic Filtering）**：
   - 3D 牌桌采用约 `56°` 俯视斜角观察牌面和牌背。`table_tile_atlas.gdshader` 仅使用 `filter_linear_mipmap`，`_material` / `_decal` 使用 `TEXTURE_FILTER_LINEAR_WITH_MIPMAPS`。斜视下 mipmap 按短轴降级，导致对家和左右家牌面、牌背明显糊化。

### 设计方案

1. **动态物理分辨率 `SubViewport`**：
   - 在 `table_scene_3d.gd` 新增 `set_render_scale(scale_factor: float)` 接口，由 `table.gd` 的 `layout_screen()` 在窗口尺寸或全屏状态变化时同步调用。
   - 计算渲染倍率：`render_scale = clampf(scale_factor, 1.0, 2.5)`（2K 下 `1.8` → 视口渲染 `2304×1440`，1080p 下 `1.35` → `1728×1080`，4K 下封顶 `2.5` → `3200×2000` 兼顾性能与显存）。
   - 逻辑画幅 `DESIGN_SIZE = Vector2i(1280, 800)` 与 `project_point` / `project_rect` / `project_face` 投影坐标完全不变（`Camera3D` 使用 `KEEP_HEIGHT` 且宽高比恒为 `16:10`，高分辨率渲染结果与逻辑投影严丝合缝）。
   - 视口尺寸变化时自动触发一次 `_request_render()`，确保窗口缩放/全屏切换同帧清晰刷新。
   - 低配/简洁档保底：`effects == "off"` 或 Android 设备可将渲染倍率上限收紧到 `1.5`（或 `1.25`），保证帧率平稳。
2. **提升牌面图集分辨率**：
   - `table_tile_atlas.gd` 将 `INK_SIZE` 从 `96×128` 提升至 **`240×320`**，`PADDING` 提升至 `Vector2i(8, 8)`（单格 `256×336`，8×6 图集总尺寸 `2048×2016`，在 OpenGL 3.3 Compatibility 下完全兼容且刚好卡在 2048 纹理档位内，兼顾显存与最高清晰度）。
   - `GOLD_BADGE` 内嵌 SVG 尺寸同步从 `48×48` 提升至 `128×128`，避免“金”字角标发虚。
   - 牌面 SVG 源图若在 `300×400` 基础上按 `240×320` 写入，无需放大即可达到 2K 满屏像素密度。
3. **提升牌背清晰度**：
   - 将 `godot/assets/tile_backs/*.svg.import` 调整为 `svg/scale=2.0`（光栅化至 `256×256`）并开启 `mipmaps/generate=true`（或在代码中生成带 mipmap 的 `ImageTexture`）。
4. **全面开启各向异性过滤**：
   - `godot/assets/effects/table_tile_atlas.gdshader`：`uniform sampler2D markings : source_color, filter_linear_mipmap_anisotropic, repeat_disable;`
   - `table_scene_3d.gd` 的 `_material()` / `_decal()`：将 `texture_filter` 改为 `BaseMaterial3D.TEXTURE_FILTER_LINEAR_WITH_MIPMAPS_ANISOTROPIC`。

## 问题三：牌张被遮挡现象的系统性排查与修复

### 全桌遮挡隐患审计

在当前相机参数（`CAMERA_POSITION = (0, 22.3, 15.5)`、`CAMERA_TARGET = (0, 0, 0.46)`、俯角约 `56°`）下，上层牌墙顶面高度约 `y ≈ 0.88`，会对牌墙后方的牌面形成透视盲区。逐一排查四家及 2D UI：

| 序号 | 遮挡现象 | 几何根因 | 严重程度 |
| --- | --- | --- | --- |
| **A** | **对家（seat 2）副露、立牌与结算亮牌被对家双层牌墙严重遮挡**（用户截图红圈所示） | 对家牌墙 `WALL_DEPTH[2] = 6.36`（后沿 `z = -6.84`，顶高 `0.88`），在相机透视下向后投射盲区直至 `z ≈ -7.52`；而对家手牌/副露中心位于 `z = -7.43`（前沿 `z = -6.95`），几乎整个被牌墙挡住大半截。 | **高（必现）** |
| **B** | **左右家（seat 1 / seat 3）副露与结算亮牌内沿贴近左右牌墙透视边缘** | 左右牌墙 `WALL_DEPTH[1/3] = 8.73`（外沿 `x = ±9.21`，顶高 `0.88`），侧向透视盲区外延至 `x ≈ ±9.49`；左右家副露/亮牌中心在 `x = ±9.97`（内沿 `±9.49`），满墙时内侧白边与牌面被牌墙啃边，加厚副露后风险更大。 | **中（满墙时可见）** |
| **C** | **本家（seat 0）牌河远行被近端双层牌墙上沿遮挡风险** | 近端牌墙 `WALL_DEPTH[0] = 5.12`，本家牌河在牌墙后方，靠 `NEAR_RIVER_WALL_CLEARANCE = 0.47` 留空。若后续微调牌墙深度或牌厚，必须保证 1~6 行（至 36 张）全部在近端墙顶面之上完整露出。 | **中（需回归护栏）** |
| **D** | **右下角 2D 操作按钮（“出牌”等）与右家立牌/副露或本家抬起手牌擦边** | 操作条固定在 `ACTION_Y = 579`，高度 55（底边 `634`），最右侧到 `x ≈ 1228`，与右家近端牌张及本家选中抬起手牌距离偏近。 | **低~中（视局面而定）** |
| **E** | **顶部对家头像框与对家外移后的手牌/副露边界** | 对家头像框 `SEAT_POSITIONS[2]` 位于 `(521, 12)`，底边约 `y = 88`。若为避开对家牌墙而把对家手牌/副露过度外推，可能撞到顶部木框或对家头像框。 | **中（修复 A 时需联动约束）** |

### 设计方案

核心思路：**通过“内收对家/左右牌墙 + 适度外推外家手牌/副露 + 精确屏幕投影防遮挡断言”形成硬几何约束**，确保四边满墙（144 张）时，所有公开牌面在屏幕空间完全不被牌墙遮挡。

1. **对家（seat 2）解遮挡（修复 A & E）**：
   - 将对家牌墙适当向桌心内收（如 `WALL_DEPTH[2]` 由 `6.36` 调整至 `5.55`~`5.70` 区间，需满足对家 36 张牌河外沿与对家牌墙前沿留足清晰安全间隙）；
   - 将对家手牌与副露深度适当外推（如 `depth` 由 `7.43` 调整至 `7.55`~`7.65`，同时确保仍在绿桌布内沿与顶部头像框 `y = 88` 以下留有安全边距）；
   - 实测校验：对家牌墙上层后棱投影后的屏幕最小 `y`（最靠上边缘），必须**大于**对家副露/亮牌前沿投影后的屏幕最大 `y`（最靠下边缘），即屏幕空间严格满足 `far_meld_face_bottom_y < far_wall_top_edge_y`，实现**零遮挡**。
2. **左右家（seat 1 / seat 3）解遮挡（修复 B）**：
   - 将左右牌墙适当内收（如 `WALL_DEPTH[1/3]` 由 `8.73` 调整至 `8.25`~`8.40`），左右家手牌/副露深度保持在 `10.05`~`10.20`（不超出桌布左右木边）；
   - 屏幕空间校验：左右牌墙上层外棱投影边缘与同侧副露/亮牌内沿投影边缘互不相交。
3. **本家（seat 0）牌河与操作区防遮挡（修复 C & D）**：
   - 复核 `NEAR_RIVER_WALL_CLEARANCE`，确保在统一厚度后，本家牌河 6/12/18/24/36 张的最后一行底边全部严格在近端上层牌墙顶边之上；
   - 检查右下角操作按钮（`ACTION_Y` / 右边距）与右家近端立牌、本家选中抬起手牌之间保持清晰间距。
4. **桌面木框与桌布尺寸联动**：
   - 如外家手牌/副露略微外移，同步检查 `CLOTH_SIZE`（当前 `21.92×16.66`）和木框四层 `rounded_slab` 尺寸，确保所有牌张与接触阴影均完整落在绿桌布之内。

## 自动化测试与视觉验收标准

1. **新增 3D 屏幕空间防遮挡硬断言（写入 `v133c_layout_test.gd` 或新增 `v133d_visual_test.gd`）**：
   - **厚度一致断言**：校验副露（含吃/碰/明杠/暗杠/补杠）与牌山、舍牌的厚度倍率一致，且补杠第四张底面不穿透来源牌顶面。
   - **四向零遮挡断言**：在 144 张满墙状态下，用同一相机投影公式计算：
     - 对家（seat 2）任意副露及结算亮牌的**整个牌面四边形**，其最大 `y` 严格小于对家双层牌墙上层投影的最小 `y`；
     - 左家（seat 3）副露及亮牌的最大 `x` 严格小于左墙外棱投影的最小 `x`；
     - 右家（seat 1）副露及亮牌的最小 `x` 严格大于右墙外棱投影的最大 `x`；
     - 本家（seat 0）6~36 张牌河任意牌面的最大 `y` 严格小于近端双层牌墙上层投影的最小 `y`；
     - 对家手牌/副露的最小 `y` 严格大于顶部头像框底边（避免被头像遮挡）。
   - **高分渲染断言**：校验 `set_render_scale(1.8)` 时 `SubViewport.size == Vector2i(2304, 1440)`（在非 headless 模式下），且 `project_point` / 命中区仍与 `1280×800` 逻辑画幅一致；图集单格 `INK_SIZE >= Vector2i(240, 320)`。
2. **实机多分辨率视觉验收**：
   - 截取并目检 **1280×800**、**1920×1080**、**2560×1440（2K 全屏）** 下的实机画面，重点放大检查：
     - 本家/对家/左右家副露厚度与牌山/舍牌完全统一；
     - 2K 全屏下牌面笔画、金标徽章、六款动物牌背边缘锐利清晰，无发糊感；
     - 满墙开局及中后盘下，对家副露/手牌、左右家副露/手牌、本家多排牌河全部完整可见，无任何遮挡。
