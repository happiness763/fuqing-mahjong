# 福清麻将 v1.3.3e 左上角金牌可读性与茶馆场景背景设计

2026-11-24 · 审阅稿

## 目标与范围

在 `v1.3.3d` 的高清 3D 牌桌基础上，重点解决两项直接影响牌局观感与信息获取的体验问题：

1. **显著提升左上角“金”栏的可读性**：放大单金与花金牌面尺寸，优化“金”字徽章与信息框排版、牌面留白和明暗对比，让玩家余光一扫即可清晰辨认本局金牌；
2. **为牌桌外围增加“融城茶馆”沉浸式场景背景**：参考腾讯《欢乐麻将》将牌桌置身于柔焦室内场景的构图思路，替换当前牌桌四周单调的纯深绿黑底色，让 3D 牌桌自然“落座”于新中式茶馆包厢环境之中，并在 16:10、16:9 及 2K 全屏下无缝铺满整个窗口。

本次改动不涉及规则、计分、AI、联机协议及 3D 牌张几何坐标；联机版本同步更新至 `1.3.3e`。

---

## 一、左上角“金”栏可读性优化

### 现状与根因

在 `godot/scripts/table.gd` 中，左上角信息框目前为 `Rect2(18, 17, 224/302, 67)`，其中的 `GoldDisplay`（`GOLD_AREA = Rect2(156, 24, 151, 52)`）存在三处导致辨识度偏低的原因：

1. **牌张尺寸过小**：单金牌仅 `30×40` px，四张花金仅 `26×34.7` px。在 2K 全屏下虽会随 UI 等比放大，但相对于主牌桌和其他牌张仍明显偏小，复杂牌面（如五筒、七索、花牌字样）缩成细碎色点；
2. **2D 牌面内边距与金底叠加**：`tile_view.gd` 绘制 2D 金牌时自带描边与暖黄底色，在小尺寸下进一步压缩了中间有效图案的占比，降低了花色笔画与底色的对比度；
3. **信息框纵向空间未充分利用**：牌桌顶部木框上沿在 `y ≈ 108` 左右，当前信息框底边仅到 `y = 84`，上方还留有充裕的视觉安全区可以适度加高。

### 设计方案

1. **扩大信息框与金牌尺寸**（保留 `y < 100` 以远离牌桌木框，保留左侧边距 `x = 18`）：
   - 信息面板高度由 `67` 提升至 **`84`**（`y: 14..98`），内部加一条极细淡金竖分隔线区分左侧局数/余牌与右侧金牌区；
   - **单金模式**：信息框宽 `252`，金牌尺寸由 `30×40` 放大至 **`48×64`**（面积提升 **2.56 倍**）；
   - **花金模式（4 张）**：信息框宽 `372`，每张花金牌尺寸由 `26×34.7` 放大至 **`38×50.7`**（面积提升 **2.14 倍**），间距宽松不粘连；
   - **“金”字印章**：放大至 `34×56` 居中对齐牌张，使用深褐金字配高对比暖金徽章底与细高光边框；
   - **联机提示位联动**：`room_notice_label` 横向起点同步右移至不与花金信息框重叠的位置（或紧贴信息框下方安全带），避免遮挡对家头像（`x = 521`）。
2. **提升 2D 金牌清晰度与对比度**：
   - 在 `tile_view.gd` 中为 `GoldDisplay` 或小尺寸 2D 牌面提供更明亮洁净的象牙暖白底（配合醒目的外圈亮金边与底部金线，而非整体偏暗泛黄的底色），放大图案绘制占比，使万/筒/条/字/花在左上角一目了然；
   - 保持 `GoldDisplay`、`GoldMark` 节点名、`GOLD_AREA.encloses(...)` 及“只显示‘金’字与牌面、不额外拼牌名文字”的契约，完全兼容现有回归测试。

## 二、牌桌外围“融城茶馆”场景背景设计

### 参考与视觉定位

参考用户提供的腾讯《欢乐麻将》对局画面，其外围背景之所以比纯色黑边更具高级感与沉浸感，核心在于三点：
- **空间纵深**：牌桌坐落在一块带透视纹理的地面/地毯之上，四周有房间透视边界而非虚空；
- **柔焦环境陈设**：屏幕上方与左右外侧点缀低饱和、景深虚化的主题摆件与暖光光源，丰富画面层次但绝不喧宾夺主；
- **光影承托**：牌桌外围有柔和的落地投影与顶部环境微光，把前景 3D 牌桌自然融入空间。

结合本项目 **“融城茶馆”** 的新中式国风茶室定位（而非卡通棋牌风），场景背景设计规范如下：

| 区域 | 视觉元素设计 | 可读性保护约束 |
| --- | --- | --- |
| **整体地面（全屏底层）** | 温润深胡桃木地板拼接 + 牌桌下方压暗的青墨色中式暗纹地毯，带与牌桌一致的轻俯视透视线条 | 整体明度控制在低中暗调，避免与绿桌布抢色 |
| **顶部远景（对家上方）** | 新中式木格栅窗棂 / 屏风柔焦远景，隐约透出茶室暖黄灯影与竹影 | 中央对家头像（`x: 420..680, y: 0..100`）后方刻意压暗虚化，确保白色文字与头像轮廓高对比 |
| **左上 / 右上外侧** | 柔焦暖光中式小宫灯/纸灯笼光晕、侧案青瓷茶壶与茶盏剪影、几枝淡墨竹叶（宽屏 16:9 / 2K 展开区尤为饱满） | 全部施加柔和景深模糊与暗角过渡，左上信息框、右上音效/菜单按钮后方保持沉稳底色 |
| **左右两侧** | 温润木质茶室边柜/圆凳柔焦剪影 + 柔和环境光晕 | 左右玩家头像框与名牌下方保持低噪点暗色过渡，不干扰“花数 / 胡·点”小字读取 |
| **牌桌交界处** | 3D 麻将桌外围叠加一圈柔和落地投影，增强桌体压在茶馆地板上的实感 | 与现有木质桌脚自然衔接，无硬切边 |

### 技术架构方案

采用 **“3D `SubViewport` 透明背景 + `table_art.gd` 全屏茶馆场景层”** 的组合方案：

1. **开启 3D 牌桌透明背景**（`godot/scripts/table_scene_3d.gd`）：
   - 将 `_viewport.transparent_bg = true`；
   - 将 `WorldEnvironment` 的 `background_mode` 保留默认清除透明（`BG_CLEAR_COLOR` 配合透明 clear color 或在 `SubViewport` 启用 `transparent_bg` 后让 3D 视口背景像素 `alpha = 0`），使 3D 视口**只输出麻将桌体与全部 3D 麻将牌**，四周自然透出底层的茶馆场景；
   - **关键优势**：不改变 3D 相机、不改变 `16:10` 逻辑投影、不破坏任何 `project_point` / 命中区坐标，同时在 16:9（1080p / 2K）宽屏下，左右扩展出的画幅与牌桌内部共用同一张连续无缝的场景背景，彻底消灭宽屏接缝！
2. **新增高清茶馆背景资源与全屏绘制**（`godot/assets/table/teahouse_bg.png` + `godot/scripts/table_art.gd`）：
   - 生成一张 `2560×1440`（16:9 2K 原生分辨率）的新中式俯视柔焦“融城茶馆”室内场景底图 `godot/assets/table/teahouse_bg.png`，并做好柔焦景深与四角暗角调色；
   - 在 `table_art.gd` 的 `_draw()` 中，当 `native_board == true` 时，不再跳过底图绘制，而是按 `background_area` 等比 cover 铺满整个真实窗口（覆盖 16:10、16:9、2K 全屏及 864×540 小窗），再叠加一层极轻的统一色调暗角（保证头像与按钮可读性）；
   - `board_art` 仍位于 `native_table` 之下（调整 `native_table` 层级为在 `board_art` 之上绘制，而非 `show_behind_parent = true`，确保绘制顺序为：`board_art` 茶馆全景背景 → `native_table` 透明 3D 牌桌 → 2D 风盘/头像/金栏/按钮/微尘！）。
   - 注意微尘效果：将 `board_art` 的微尘或光斑保持在 3D 牌桌之上（或由独立前景层/保留在 `fx`），避免被 `native_table` 遮住；
3. **特效档位与性能**：
   - 仅增加一张静态全屏贴图绘制与 `SubViewport` alpha 混合，**零额外 3D 几何体与阴影开销**，2K 全屏帧率基本无损；
   - “完整”档显示茶馆场景背景 + 柔和浮尘；“简洁”与“关闭”档保留静态茶馆场景背景、关闭动态浮尘。

## 三、验收标准

1. **左上角“金”栏验收**：
   - 单金与四张花金在 1280×800 与 2560×1440 下均清晰易辨，无需凑近即可一眼认出牌面；
   - 不与顶部木框、联机提示或对家头像重叠；
   - `desktop_test.gd` 中的 `test_gold_display` 与 `test_flower_gold` 全部通过。
2. **茶馆场景背景验收**：
   - 在 1280×800（16:10）、1920×1080（16:9）、2560×1440（2K 全屏）及 864×540 下均无缝铺满全屏，无黑边、无接缝、无拉伸变形；
   - 3D 牌桌边缘干净无白边/锯齿，自然融入茶馆地面；
   - 四家头像、名牌、左上金栏、右上按钮、右下操作按钮在背景上保持高对比、易读；
   - 首页大厅与返回首页切换时背景状态干净复位。
3. **回归与本地交付**：
   - 全部 Godot 回归测试（30+ 用例）与 Web 测试（13 用例）通过；
   - 更新 `docs/images/gameplay.png`、`README.md` 与 `release/` 说明，本地导出并冒烟验证 `FuqingMahjong-v1.3.3e.exe` 与 `FuqingMahjong-v1.3.3e-windows.zip`（不推送 GitHub）。
